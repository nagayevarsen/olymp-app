# Шпаргалка для защиты

## Шаг 1. Подготовка проекта

- **Виртуальное окружение (`.venv`)** — отдельная папка с библиотеками только для этого проекта. Они не смешиваются с другими программами на компьютере.
- **`requirements.txt`** — список библиотек с точными версиями, чтобы проект одинаково запускался на любом компьютере и на сервере.
- **`.gitignore`** — список того, что нельзя отправлять в репозиторий. Главное в нём — файл `.env` с секретными ключами.

## Шаг 2. Логика дат и тесты

- **Почему даты проверяет код, а не ИИ?** Сравнение дат — точная задача. Код всегда даёт один и тот же ответ, а ИИ может ошибиться.
- **Почему время задано как UTC+5?** В Казахстане единый часовой пояс. Результат не зависит от настроек компьютера: день меняется ровно в полночь по Казахстану.
- **Что будет с датой без года?** Такая дата считается неизвестной. Приложение покажет «дата следующего этапа не объявлена» и не будет обещать, что регистрация открыта.
- **Если дедлайн сегодня, регистрация ещё открыта?** Да, сегодняшний день считается последним днём регистрации.
- **Зачем нужны тесты?** Это маленькие программы, которые проверяют основную. Если при изменении кода что-то сломается, тест сразу покажет, какой случай перестал работать.
- **Зачем таблица `date_cases.json`?** Офлайн даты считает браузер на JavaScript. Одна таблица случаев нужна, чтобы Python и JavaScript считали одинаково.

Как запустить тесты: `.venv\Scripts\python -m pytest`

## Шаг 3. Каталог и проверка данных

- **Где лежат данные?** В файле `data/events.json`. Только факты и ссылка на официальный источник, чужие тексты и картинки не копируем.
- **Зачем проверка данных?** Каталог заполняют вручную, а человек может ошибиться. Код проверяет каждую запись, прежде чем её показать.
- **Чем ошибка отличается от предупреждения?** При ошибке запись не показываем, например, если нет официальной ссылки. При предупреждении показываем, но неправильную дату считаем неизвестной.
- **Почему в файле `math`, а не «Математика»?** Это код предмета. Перевод хранится отдельно, поэтому одни и те же данные работают на всех языках, а опечатка не создаст лишний предмет в фильтре.

Как проверить файл после правки: `.venv\Scripts\python -m catalog.events`

## Шаг 4. Сервер и первая страница

- **Как устроено приложение?** Браузер запрашивает у сервера страницу, а затем список событий. Сервер читает файл, считает статусы и отправляет ответ в формате JSON. JavaScript рисует из него карточки.
- **Как защищена страница?** Данные выводятся как обычный текст, а опасные ссылки вроде `javascript:` отсеивает проверка данных.
- **Что будет, если файл данных сломан?** Приложение не падает: сервер записывает причину в журнал, а пользователь видит понятное сообщение.

Как запустить: `.venv\Scripts\python app.py`, затем открыть http://127.0.0.1:5000
