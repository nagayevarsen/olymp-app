# Шпаргалка для защиты

## Шаг 1. Подготовка проекта

- **Виртуальное окружение (`.venv`)** — отдельная папка с библиотеками только для этого проекта. Они не смешиваются с другими программами на компьютере.
- **`requirements.txt`** — список библиотек с точными версиями, чтобы проект одинаково запускался на любом компьютере и на сервере.
- **`.gitignore`** — список того, что нельзя отправлять в репозиторий. Главное в нём — файл `.env` с секретными ключами.

## Шаг 2. Логика дат и тесты

- **Почему даты проверяет код, а не ИИ?** Сравнение дат — точная задача. Код всегда даёт один и тот же ответ, а ИИ может ошибиться.
- **Почему время задано как UTC+5?** В Казахстане единый часовой пояс. Результат не зависит от настроек компьютера: день меняется ровно в полночь по Казахстану.
- **Что будет с датой без года?** Такая дата считается неизвестной. Приложение покажет «дата следующего этапа не объявлена» и не будет обещать, что регистрация открыта.
- **Если дедлайн сегодня, регистрация ещё открыта?** Да, сегодняшний день считается последним днём регистрации.
- **Зачем нужны тесты?** Это маленькие программы, которые проверяют основную. Если при изменении кода что-то сломается, тест сразу покажет, какой случай перестал работать.
- **Зачем таблица `date_cases.json`?** Офлайн даты считает браузер на JavaScript. Одна таблица случаев нужна, чтобы Python и JavaScript считали одинаково.

Как запустить тесты: `.venv\Scripts\python -m pytest`

## Шаг 3. Каталог и проверка данных

- **Где лежат данные?** В файле `data/events.json`. Только факты и ссылка на официальный источник, чужие тексты и картинки не копируем.
- **Зачем проверка данных?** Каталог заполняют вручную, а человек может ошибиться. Код проверяет каждую запись, прежде чем её показать.
- **Чем ошибка отличается от предупреждения?** При ошибке запись не показываем, например, если нет официальной ссылки. При предупреждении показываем, но неправильную дату считаем неизвестной.
- **Почему в файле `math`, а не «Математика»?** Это код предмета. Перевод хранится отдельно, поэтому одни и те же данные работают на всех языках, а опечатка не создаст лишний предмет в фильтре.

Как проверить файл после правки: `.venv\Scripts\python -m catalog.events`

## Шаг 4. Сервер и первая страница

- **Как устроено приложение?** Браузер запрашивает у сервера страницу, а затем список событий. Сервер читает файл, считает статусы и отправляет ответ в формате JSON. JavaScript рисует из него карточки.
- **Как защищена страница?** Данные выводятся как обычный текст, а опасные ссылки вроде `javascript:` отсеивает проверка данных.
- **Что будет, если файл данных сломан?** Приложение не падает: сервер записывает причину в журнал, а пользователь видит понятное сообщение.

Как запустить: `.venv\Scripts\python app.py`, затем открыть http://127.0.0.1:5000

## Шаги 5–7. Главный экран, форма поиска и сохранение

- **Почему логика дат есть и в Python, и в JavaScript?** Сервер проверяет данные, а браузер пересчитывает статусы, чтобы они были верными даже офлайн. Обе версии проверяются одной таблицей, поэтому считают одинаково.
- **Как работает выбор даты?** Для каждого события код проверяет, была бы регистрация открыта в выбранный день. Прошедшую дату выбрать нельзя, поэтому закрытое событие не выглядит действующим.
- **Почему возраст не вычисляется из класса?** В одном классе учатся дети разного возраста, и формула могла бы скрыть подходящую олимпиаду. Событие убирается, только если организатор сам указал ограничение.
- **Что если цена неизвестна?** Событие видно при «любой стоимости», но не попадает ни в «бесплатно», ни в «платно»: мы не обещаем того, чего не знаем.
- **Где хранятся сохранения?** Только в браузере пользователя, поэтому регистрация не нужна. Чтобы перенести их на другое устройство, приложение делает ссылку со списком событий. Сервер её не хранит.
- **Попадают ли данные пользователя на сервер?** Нет. Отбор идёт прямо в браузере, поэтому форма работает быстро и ничего не отправляет.

## Задания прошлых лет

- **Почему только ссылки?** Задания принадлежат организаторам, поэтому мы не копируем файлы, а ведём на официальную страницу.
- **Как задания связаны с олимпиадой?** У них одинаковый код `series_id`. Поэтому в карточке олимпиады есть список «Прошлые олимпиады», где можно выбрать любой год и этап.

## Темы и дизайн

- **Как сделаны две темы?** Все цвета заданы переменными. Тёмная тема меняет значения переменных, а не всю вёрстку, поэтому стоит очень мало кода.
- **Какая тема откроется?** Сначала та, что выбрана в настройках устройства. Кнопка меняет её, а выбор запоминается на этом устройстве.

## Офлайн-режим и установка (PWA)

- **Что такое PWA?** Сайт, который можно установить на экран телефона и открывать как приложение, без магазина приложений.
- **Как работает без интернета?** Service worker при первом открытии сохраняет файлы и каталог, а потом отдаёт копии, если сервер недоступен.
- **А если данные устарели?** Статусы всё равно считаются по сегодняшней дате прямо на устройстве, поэтому прошедшие события закрываются и офлайн. Если данные загружены не сегодня, приложение предупреждает об этом.
- **Как это проверяли?** Открыли приложение, полностью остановили сервер и открыли снова: каталог, сохранённое и задания показались.

## Приватность

- **Почему нет регистрации?** Большинство пользователей несовершеннолетние, поэтому мы не собираем их данные: нет данных — нечему утекать. Все условия поиска и сохранения остаются на устройстве.
- **Что значит «Сохранить»?** Запись в памяти браузера. Если очистить данные браузера, сохранённое пропадёт, поэтому есть ссылка для переноса.

## Качество кода

- **Что такое CI?** GitHub сам запускает тесты при каждой отправке кода (`.github/workflows/tests.yml`). Если что-то сломалось, это видно сразу.
- **Как разделён код?** Логика (`dates`, `filters`, `events`) отделена от отображения (`app.js`), поэтому её можно проверять тестами без браузера.
